# Release 0.5.1 — Make the human-approval gate structural

**Tag:** `0.5.1` · **Status:** shipped · **Theme:** close a gate-bypass found in the E2E review — scope the
agent's sim service token to read-only, so the only path to a bed change is the human-approval gate (R7).

> Builds on [0.5.0](./0.5.0.md). A security patch in the auth layer only; the agent, simulator, and eval are
> untouched. Built spec-first (`spec/agent-gate/`). Closes #42.

---

## The product (unchanged)

An AI assistant for a hospital bed-flow coordinator: it watches a simulated hospital, predicts where beds
will run short, explains why, and proposes ranked fixes a human approves before anything changes. Synthetic
data only; no clinical decisions. See [0.1.0](./0.1.0.md) for the full product + architecture.

## What changed (the gate)

The OpenCode agent reaches the sim API server-to-server with a shared **service token** (it has no browser
session). That token was scoped to the whole `/api/sim/*` subtree — which **includes the mutating routes**
(`/actions/*`, `/step`, `/scenario`) — and the service principal carried `role: coordinator`, so it cleared
the operator check. The result: the agent's `expedite_script` / `request_transport` tools could `fetch` a
mutating endpoint and change beds **without a human approval**, gated only by OpenCode's harness `ask` —
exactly what `CLAUDE.md` says must never be the real gate. A bypassing mutation also produced **no
`DecisionRecord` and no actor** (a silent R10 gap).

The fix reuses the existing policy classification (read routes are tier `authenticated`; mutating routes are
`operator`):

- **Default-deny read-only allow-list.** `simServiceCaller` now admits the token **only** on the three read
  endpoints the agent's perceive + forecast tools actually call — `/api/sim/state`,
  `/api/sim/forecast/discharges`, `/api/sim/forecast/demand`. Every other path (mutating routes included) is
  not a credential → falls through to the session check → `401`. A new agent read tool must add its endpoint
  to the set.
- **Least-privilege principal.** The synthetic agent principal is now `viewer`, not `coordinator` — it can
  never clear an operator check, so even a future route misclassification can't hand it a mutating route
  (belt-and-braces with the allow-list).

**Result:** `Driver.approve()` is now the **sole** writer to the simulator. R7 (human approval) and R10
(every change has a `DecisionRecord` + actor) hold **by construction**, not by the agent's good behaviour
plus a harness setting. The harness `ask` and the action tools stay as redundant defence-in-depth.

## Architecture impact

- One function + one constant in `src/auth/session.ts`; no new deps, no migration, no API-surface change.
- The edge middleware's service-token check stays **optimistic** (lets a token-bearing `/api/sim/*` request
  past the default-deny gate); the **authoritative** read-only scope lives in `session.ts`, which refuses
  the mutating routes — correct fail-closed layering.
- The OpenCode SDK stays isolated to `adapter.ts`; the agent loop, simulator, eval, and approval UX are
  unchanged.

## Verification

`typecheck` · `lint` · `build` clean; **182 tests** green (+8) — the `auth-policy` enumeration test now also
fires the agent's own token at every mutating sim route (each refused `401`, state unchanged), confirms the
three read routes still admit it, and pins the principal to `viewer`. S12/S13 unaffected. Live-verified in
Docker: with the service token, `GET /api/sim/state` → `200`, all of `/api/sim/actions/*`, `/step`,
`/scenario` → `401`; a wrong token → `401`. Full detail: `spec/agent-gate/`.
