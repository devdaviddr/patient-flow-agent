# Release 0.4.0 — Real self-hosted auth + attributed approvals

**Tag:** `0.4.0` · **Status:** shipped · **Theme:** replace the `0.3.0` mock login with real,
self-hosted authentication, and attribute every approval to the signed-in person.

> Builds on [0.3.0](./0.3.0.md). Adds a new auth layer plus three small seams into existing code
> (middleware, route guards, one field on `DecisionRecord`); the agent, simulator, and eval are
> untouched. Built spec-first (`spec/auth/`).

---

## The product (unchanged)

An AI assistant for a hospital bed-flow coordinator: it watches a simulated hospital, predicts where beds
will run short, explains why, and proposes ranked fixes a human approves before anything changes.
Synthetic data only; no clinical decisions. See [0.1.0](./0.1.0.md) for the full product + architecture.

## What changed (auth)

- **Better Auth + SQLite/Drizzle** — real email/password accounts, passwords stored as a KDF hash,
  **server-side DB-backed sessions** (revocable on logout). Synthetic `.test` identities only — no PII.
- **Two roles, `viewer ⊂ coordinator`** — coordinators approve/reject and run the agent; viewers are
  read-only. The role rides on the validated session so guards read it server-side.
- **Fail-closed enforcement** — a default-deny **edge middleware** (optimistic cookie check) over every
  `(app)` page + `/api/*` route, backed by the authoritative **`withPolicy`** per-route guard (Node
  runtime). Every route is explicitly classified; an unmapped route defaults to the most restrictive tier
  and **fails CI** — proven by an enforcing enumeration test.
- **Attributed approvals** — `DecisionRecord.actor` records *who* approved/rejected (a denormalized
  snapshot, so the audit trail survives a future account deletion). The timeline shows "Approved by …".
- **Per-IP sign-in rate limiting** keyed on `CF-Connecting-IP` behind the tunnel.
- **Two seeded demo accounts** (coordinator + viewer), click-to-fill on the login screen.

## Architecture impact

- New `src/auth/*` layer (Better Auth server, Drizzle schema/store, session guards, policy + `withPolicy`,
  seed) + `src/middleware.ts`; `DecisionRecord` gains `actor`. The OpenCode SDK stays isolated to
  `adapter.ts`; the human-approval gate is unchanged.
- **Ingress is a Cloudflare Tunnel** — the app port is no longer published; the origin is unroutable, edge
  TLS keeps the `Secure` cookie valid, and the real client IP arrives as `CF-Connecting-IP`. Accounts +
  sessions live on a **SQLite volume** that survives a container restart. Docker first-boot applies
  migrations and runs the idempotent seed.
- New deps (exact pins): `better-auth`, `drizzle-orm`, `better-sqlite3`, `drizzle-kit`.

## Also in this release

- **Logout/blank-screen fix** — the optimistic middleware can't validate a present-but-invalid cookie
  (logout, or a stale cookie), so the `(app)` layout now redirects to `/login` instead of rendering a blank
  shell. Pinned by a unit test (`tests/auth-gate.test.ts`).
