# Release 0.5.0 — Onboarding & administration

**Tag:** `0.5.0` · **Status:** shipped · **Theme:** make auth usable beyond seeded accounts — invite-gated
sign-up, a superadmin who administers users, and self-service account management.

> Builds on [0.4.0](./0.4.0.md). Same fail-closed enforcement model, extended one tier and three surfaces.
> The agent, simulator, and eval are untouched. Built spec-first (`spec/auth-onboarding/`).

---

## The product (unchanged)

An AI assistant for a hospital bed-flow coordinator: it watches a simulated hospital, predicts where beds
will run short, explains why, and proposes ranked fixes a human approves before anything changes.
Synthetic data only; no clinical decisions. See [0.1.0](./0.1.0.md) for the full product + architecture.

## What changed (onboarding + administration)

- **Invite-gated sign-up** — 50 single-use, role-bearing keys (≥128-bit, base32), stored **hashed**
  (HMAC-with-secret, never plaintext; plaintext emitted once to a gitignored file). A public `/register`
  page redeems a key and signs you in; the role is encoded on the key (`viewer`/`coordinator`, never
  superadmin). Redemption is **claim-then-compensate**: the conditional `UPDATE … WHERE used_by IS NULL` is
  the atomic race guard, so concurrent redeemers can't both win.
- **Superadmin tier + admin area** — the hierarchy is now `viewer ⊂ coordinator ⊂ superadmin`. A
  superadmin-only `/admin` page (Better Auth **admin plugin**) lists users, changes roles, removes
  accounts, and shows the invite overview. The admin endpoints are **independently re-gated** to superadmin
  at the route layer, so the plugin is never the sole authority.
- **No lockout** — the **last superadmin can't be deleted or demoted**, enforced by **SQLite triggers**
  (a DB-level guard) on every path: the admin area *and* self-service delete.
- **Self-service lifecycle** — change password (current password required) and delete your own account
  (sessions cascade → `/login`); prior `DecisionRecord`s survive via the denormalized actor.
- **Superadmin is never advertised** — bootstrap-only, out-of-band password (printed once at seed); the
  login screen still shows only the viewer/coordinator demo accounts.

## Architecture impact

- New `src/auth/invite.ts`, `superadmin.ts`, `same-origin.ts`; the admin plugin on the Better Auth server;
  the `superadmin` policy tier + `requireSuperadmin` guard; a new `invite` table and the admin-plugin
  columns, plus the last-superadmin triggers (migration `0001`). New routes: `/api/register`,
  `/api/account` (+ `/password`), `/api/admin/invites`. New pages: `/register`, `/admin`, and the extended
  Settings.
- The OpenCode SDK stays isolated; the agent/sim/eval and the human-approval gate are unchanged.

## Implementation notes (deviations from plan)

Three refinements, each strengthening a decision rather than changing it (detail in
`spec/auth-onboarding/implementation.md §7`): register creates accounts via the server-controlled
`internalAdapter` (the admin plugin's `create-user` needs an admin caller); the last-superadmin invariant
is enforced by DB triggers rather than a framework hook; app roles are mapped onto the admin plugin's
access-control sets.
