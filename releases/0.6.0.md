# Release 0.6.0 — Ground the agent's plan against the live world

**Tag:** `0.6.0` · **Status:** shipped · **Theme:** the first of the agent-reasoning
improvements (#74) — a hallucinated or mismatched proposal is now caught at the
boundary instead of silently no-opping on approval.

> Builds on [0.5.1](./0.5.1.md). A driver-layer change only; the simulator, auth, and
> harness are untouched. Built spec-first (`spec/agent-grounding/`). Closes #74 item 1.

---

## The product (unchanged)

An AI assistant for a hospital bed-flow coordinator: it watches a simulated hospital,
predicts where beds will run short, explains why, and proposes ranked fixes a human
approves before anything changes. Synthetic data only; no clinical decisions.
See [0.1.0](./0.1.0.md) for the full product + architecture.

## What changed (plan grounding)

The orchestrator's plan was parsed and surfaced as approvable with **no check against
reality**. A hallucinated `targetPatientId`, or a wrong action for a patient's real
blocker (e.g. `request_transport` for a `placement`-blocked patient), still looked
valid — then on approval `Simulator.resolveBlocker` **safely no-opped** (its
precondition: the patient must exist and be blocked on exactly that type). So a
plausible-but-wrong plan degraded to a **silent zero-effect approval**.

The fix lifts that same precondition to the boundary:

- A pure `groundInterventions(interventions, state)` (`src/driver/grounding.ts`)
  partitions the plan into **grounded** (patient exists + blocker matches the action)
  and **dropped** (with a reason). It reuses the action→blocker map `approve()` uses —
  now the single source — so **"surfaced" ⇔ "`resolveBlocker` will apply"** by
  construction.
- `Driver.applyPlan` surfaces only the grounded interventions and records the dropped
  count + reasons on the `plan` decision record, so the drop is **visible in the audit
  trail (R10)**, not hidden.

Result: a coordinator is only ever offered actions that will actually free a bed; an
approval can no longer be a silent no-op, and the agent's hallucinations are logged.

## Architecture impact

- One new pure, model-free module + a few lines in `Driver.applyPlan`; the action→blocker
  map moved into the new module. No new deps, no schema/migration, no API/UI change.
- The R7 gate (`#42`) is complemented, not changed: nothing changes without approval,
  and nothing approvable is a no-op. S12 (sim only read) and S13 (drop reasons are
  logistics strings) untouched.

## Verification

`typecheck` · `lint` · `build` clean; **257 tests** green (+5) — grounding keeps a
matching intervention, drops a non-existent patient and a blocker mismatch, preserves
order; and a driver-level test proves only the grounded item is surfaced + approvable
while the plan record notes "dropped 2 ungrounded". Full detail: `spec/agent-grounding/`.
