# Release 0.6.1 — Select the model from OpenCode's configured providers (+ OpenRouter)

**Tag:** `0.6.1` · **Status:** shipped · **Theme:** the AI-config model picker now reflects
the providers/models OpenCode *actually has*, queried live — and OpenRouter is wired in.

> Builds on [0.6.0](./0.6.0.md) + the runtime AI config (#56). Adds a live model list and
> provider-credential wiring; the agent reasoning, sim, and gate are untouched. Built
> spec-first (`spec/agent-models/`). Closes #75.

---

## The product (unchanged)

An AI assistant for a hospital bed-flow coordinator: it watches a simulated hospital,
predicts where beds will run short, explains why, and proposes ranked fixes a human
approves. Synthetic data only; no clinical decisions. See [0.1.0](./0.1.0.md).

## What changed (model selection)

The AI-config Settings panel (#56) set the model from a **hardcoded** preset list — a
user could type a model OpenCode couldn't serve, and the list drifted from reality.

Now the picker is driven by what OpenCode actually has:

- **`adapter.ts: listModels()`** calls OpenCode's `config.providers()` and flattens it to
  `provider/model` choices (SDK stays isolated; returns `[]` if the harness is down).
- **`GET /api/agent/models`** (operator) serves the list; the Settings panel renders a
  `<select>` **grouped by provider**, with a **free-text fallback** when OpenCode is
  unreachable (Settings never breaks).
- **Validation:** saving a model OpenCode can't serve is rejected (`400`) when the list is
  verifiable; allowed when the harness is unreachable (can't verify — the runtime failure
  then surfaces via the assessment error path). The S13 prompt check is unchanged.
- **Providers via config:** OpenCode lists env-keyed providers, so the only wiring needed
  is credentials. **`OPENROUTER_API_KEY`** is now passed to the harness container (and
  `ANTHROPIC_API_KEY` already was) — set a key and that provider's models appear in the
  picker with **no app change**. Zen stays the zero-config default (public free tier).

## Architecture impact

- One new adapter function + a thin operator route + Settings picker + compose/`.env`
  wiring. No schema/migration. SDK access confined to `adapter.ts`.
- The swappable-provider design is now concrete: Zen out of the box; Claude / OpenRouter /
  local Ollama by adding a key to the harness env.
