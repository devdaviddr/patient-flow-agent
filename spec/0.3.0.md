## Professional UX + live agent visibility ✅

**Problem:** the app worked but *looked* like a dev console — a dark single page with no navigation,
identity, or structure — which undersells it to a coordinator or a reviewer.

**Delivers:** a calm, light, **clinical-grade** front end anyone (medical or not) can read, plus a window
into the agent as it works. Same `/api/*` routes, same agent loop — a new shell + theme around it.

### Acceptance — the shell (H1–H12)
Light **medical theme** (clinical blue on white, status colours re-mapped) replacing the dark one (H1);
a persistent **app shell** (H2) — **topbar** with app name left + avatar right (H3) and a **sidebar** of
icon+label nav with **logout pinned bottom** (H4) that **collapses to an icon rail** (persisted) (H5);
a **login** screen with **mock auth** (H6) + a redirect **route guard** (logout → /login) (H7); the
**dashboard** re-laid-out with deliberate placement (H8); a **settings** screen (scenario/seed · model ·
profile) (H9); fixed shell + independent scroll holding at common widths (H10); minimal & professional
throughout (H11); **no regressions** — agent/sim/driver/eval unchanged, 38 tests + typecheck/lint/build
green (H12).

### Acceptance — readability + live agent (U1–U11)
**Patient identities** (name + UR) on the board, cards, queues, flagged (U1); **bed-board on its own
full-width row**, 10 beds across on wide screens (U2); **Inter** self-hosted via `@fontsource` (offline
build) (U3); an **About** page (business flow + architecture) with themed **Mermaid** diagrams, in the
sidebar (U4); **plain-English** intervention cards ("Chase pharmacy · *Name*") + a renamed KPI panel
("Does the agent help?") with plain measures (U5); dedicated **ED queue** + **Discharge queue** panels of
patient cards (U6); an **accordion** dashboard — ED queue · Discharge · Proposed · Flagged · Assessment in
one row, **one open at a time** (open on the left, the rest as banners) (U7); a **live Assessment panel**
streaming each tool **call + result** (incl. subagent delegation) with a spinner + Re-assess (U8); a
**floating chat** assistant (U9); **real-time Play** auto-tick (U10); all app times via **dayjs**
(`DD-MM-YYYY HH:mm`), incl. humanised decision-timeline and rationale text (U11).

### Key decisions
**Tailwind v4** with light theme tokens; **clinical blue `#2c7be5`** on `#f7f9fc`/white (status colours
stay semantic); **lucide-react** icons + **Inter**; **mock auth** = client context + `localStorage`
guard; App Router **route group `(app)`** for the shell + standalone `/login`; the working columns are an
**accordion** (one open). The live log **polls** the OpenCode session messages (vs SSE) for simplicity.

### The two non-cosmetic additions (both keep safety + determinism green, SDK isolated to `adapter.ts`)
- **Patient identities** — deterministic `patientName(id)` / `patientUr(id)` in `src/sim`.
- **Live assessment** — `Driver.startAssessment()` runs the agent in the background;
  `planViaOrchestratorLogged()` reports its tool calls/results. The human-approval gate is untouched.

**Deps added:** `tailwindcss` + `@tailwindcss/postcss` (v4) · `lucide-react` · `@fontsource/inter` ·
`dayjs` · `mermaid`.

**Evidence:** `typecheck`/`lint`/`build` clean; **38 tests** green; live-verified in Docker
(login → dashboard → Assess streams the agent → approve → KPIs). As-built file map in the original
`spec/ux-redesign/implementation.md §7` (git history).
