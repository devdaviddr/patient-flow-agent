## 1 · Simulator — the environment (Phase 1) ✅

**Delivers:** a synthetic hospital on a seedable clock — `WorldState` (1 ED + two 10-bed wards), five
`SimEvent` kinds through one pure reducer, two scenarios (`normal-weekday`, `flu-surge`), exposed over
`GET /state` + `POST /step`. The foundation everything reads.

**Acceptance (B1–B9):** data model matches `Architecture §5` (B1); 1 ED + 2×10 beds (B2); state mutates
**only** via the reducer (B3); seedable → identical stream (B4); two scenarios (B5); `GET /state` +
ordered events (B6); forecast/action routes stubbed for Phase 2 (B7); reachable at `SIM_URL` so the
harness drops its mock (B8); determinism (S12) + ordering (S1) tests green (B9).

**Key decisions:** pure framework-agnostic core in `src/sim/` + thin Next.js routes; hand-rolled Next.js
bootstrap (not `create-next-app`, which won't overlay the existing repo); seeded mulberry32 PRNG — **no
`Math.random`/`Date.now` in `src/sim`**; module-level sim singleton for the dev server.

## 2 · Tools + Safety (Phase 2) ✅

**Delivers:** the tools bridge made real — transparent forecast heuristics (with rationale), action
endpoints that emit real `blocker_resolved` events, the harness tools pointed at the live sim, and the
**safety invariant test**.

**Acceptance (C1–C9):** `/forecast/discharges` + `/forecast/demand` return predictions with non-empty
`rationale` (C1–C2); forecasts deterministic, no model (C3); `expedite_script`/`request_transport`
clear the matching blocker (C4–C5); non-matching = safe no-op (C6); tools hit real endpoints, no
`_mock`/`_stub` (C7); `tests/safety.test.ts` finds no clinical vocabulary in tools/prompts/outputs (C8,
S13); full gate green (C9).

**Key decisions:** forecast logic lives in `src/sim` (only hospital-aware code); each action clears
**only its own** blocker type; **dropped** the tools' mock/stub fallback (a down sim surfaces as an
error, never fake data). *(The safety test caught real leaks — "diagnose"/"acuity" in prompts — twice.)*

## 3 · OpenCode Harness — the agent runtime (Phase 3) ✅

**Delivers:** the agent runtime as **configuration, not code** — one primary orchestrator + two
read-only subagents (`discharge`, `demand`) + five tools, on the free OpenCode Zen tier.

**Acceptance (A1–A10):** `opencode serve` starts headless (A1); loads the 3 agents (A2) and 5 tools
(A3); orchestrator gets all read tools + the two action tools gated `ask` (A4); subagents read-only,
action tools denied (A5); subagent models set explicitly (A6); a prompt yields a `world_state` call
(A7); no clinical vocabulary anywhere (A8, S13); default path needs **no key / no local server** (A9);
OpenCode version pinned (A10).

**Key decisions:** **OpenCode Zen `opencode/big-pickle`** as the default for all three agents
(zero-key, zero-cost demo; Claude/Ollama remain swappable); one primary + two read-only subagents so the
action capability lives in exactly one agent; build-your-own pinned harness image (`opencode-ai@1.17.3`).

## 4 · Loop Driver + Approval Gate (Phase 4) ✅

**Delivers:** the outer control loop and the **real human-approval gate** — the agent *proposes* (a
strict JSON plan); a human approves/rejects item-by-item; only then does the driver execute, in-process.

**Acceptance (D1–D8):** only `adapter.ts` imports the SDK (D1); `tick()` = one prompt → proposals, no
execution (D2); approve runs exactly one action, reject changes nothing (D3, R7/S6); re-plan on
approve/clock, traceable (D4, S7); every gap/plan/action recorded (D5, S9); the gate is the driver's,
**not** the harness `ask` — proven offline (D6); headless-testable (D7); gate green (D8).

**Key decisions:** agent returns a **strict JSON plan**, zod-validated (1 retry, never a silent empty
plan); driver executes approved actions **in-process** via `getSimulator().resolveBlocker`; decision
records in-process; planner + sim **injectable** so the gate tests run offline & deterministically.

## 5 · Web UI — the dashboard (Phase 6) ✅

**Delivers:** the human surface — bed-board, approval cards, decision timeline, KPI panel, question box,
clock controls — plus the driver's browser-facing routes.

**Acceptance (E1–E9):** live bed-board (E1); step + load scenario (E2); **Assess** → ranked approval
cards (E3); approve updates the board, reject doesn't (E4, R7/S6); decision timeline (E5); plain-language
Q&A (E6, R9); KPI placeholder (E7); `/api/driver/*` routes + singleton (E8); full browser walkthrough +
gate green (E9).

**Key decisions:** hand-rolled CSS, no Tailwind; one single-page client dashboard; **refresh-after-action**
(no websockets); Q&A via `/api/driver/ask`; driver exposed via a globalThis-cached singleton.

## 6 · Eval + KPIs — the evidence (Phase 7) ✅

**Delivers:** the headline — a headless with/without-agent run over a seeded day computing two flow KPIs,
proving **S11**.

**Acceptance (F1–F8):** `FlowKPIs { accessBlockHours, endOfDayHeadroom }` from a headless run (F1);
with/without per scenario → `EvalResult` (F2); KPIs computed exactly (F3); **S11** — with-agent beats
without on **both** metrics in **both** scenarios, asserted by a test (F4); reproducible (F5, S12); shown
in the KPI panel (F6, S10); `npm run eval` prints it (F7); gate green (F8).

**Result (deterministic):** normal-weekday access-block **9.0 vs 14.5**, headroom **2 vs 1**; flu-surge
**44.5 vs 84.5**, **2 vs 1**.

**Key decisions:** a **deterministic oracle policy** (same actionable interventions the agent proposes) is
the default "agent" — reproducible, CI-safe S11; real-LLM-agent eval is an optional N=3 mode, off by
default; 48 ticks, policy every tick; `src/eval` uses relative imports so `npm run eval` runs under `tsx`
with no SDK. **Fairness fix:** split the sim PRNG into independent arrival vs event streams so the agent's
actions can't perturb the arrival schedule (the two runs are now the same day). Scenario rates + LOS
tuned into the band where without-agent clogs but with-agent keeps up.

## Cross-cutting (Phases 0 & 8)

- **Phase 0 Bootstrap:** Next.js (App Router) + TypeScript strict + Vitest + ESLint; pinned deps.
- **Phase 8 Polish:** README demo flow + results, `docs/SUCCESS_CRITERIA.md` (S1–S13 → evidence),
